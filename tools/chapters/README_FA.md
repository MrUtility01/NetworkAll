# ساختار ماژولار فصل‌ها

هر فصل را در پوشه‌ای مستقل نگه دارید. این مسیر توسط ادغام‌ساز اندروید و واردکنندهٔ SQLite ویندوز خوانده می‌شود. فایل‌ها منبع اصلی محتوای افزوده‌اند و فصل‌های موجود را حذف یا جایگزین نمی‌کنند:

```text
tools/chapters/
  README_FA.md
  69-linux/
    chapter.json
  70-git/
    chapter.json
```

هر فایل JSON باید یک بستهٔ محتوای استاندارد داشته باشد و در ریشهٔ آن `chapter_order`، `chapter_title_fa` و `chapter_title_en` تعریف شود. محتوای آموزشی در آرایهٔ `lessons` قرار می‌گیرد.

نمونهٔ حداقلی:

```json
{
  "schema_version": 1,
  "chapter_order": 69,
  "chapter_title_fa": "فصل ۶۹: لینوکس",
  "chapter_title_en": "Linux Administration",
  "lessons": [
    {
      "uid": "lesson:ch69:linux:0001",
      "subchapter_order": 1,
      "lesson_order": 1,
      "level": "L1",
      "title_fa": "ساختار فایل‌سیستم لینوکس",
      "title_en": "Linux Filesystem Hierarchy",
      "summary": "آشنایی با مسیرها و پوشه‌های اصلی لینوکس.",
      "full_content": "## هدف\nشناخت مسیرهای اصلی فایل‌سیستم و کاربرد آن‌ها.\n\n## آزمایش\nدستور `ls -la /` را اجرا و خروجی را بررسی کنید.",
      "commands": "ls -la /",
      "examples": "ls -la /",
      "notes": "lab: inspect the root filesystem"
    }
  ]
}
```

## قرارداد محتوا

- `chapter_order` شمارهٔ فصل مقصد است. برای افزودن درس به فصل موجود همان شماره را بنویسید؛ برای فصل جدید از شمارهٔ آزاد استفاده کنید. چند فایل می‌توانند یک `chapter_order` مشترک داشته باشند.
- هر درس یک `uid` پایدار و یکتا داشته باشد.
- برای سازگاری، `title_fa`, `summary`, `full_content`, `commands`, `examples` و `notes` را نگه دارید.
- محتوای هر فصل را فقط در پوشهٔ خودش نگه دارید؛ از قرار دادن توکن، رمز، دیتابیس شخصی یا اطلاعات محرمانه در Git خودداری کنید.
- اندروید: `python scripts/export_android_index.py` سپس `python scripts/merge_content_packs_into_android.py` اجرا شود؛ ادغام‌ساز محتوای موجود را نگه می‌دارد و درس‌های ماژولار را اضافه می‌کند.\n- ویندوز: فایل‌ها هنگام راه‌اندازی سرور به‌صورت افزایشی وارد SQLite می‌شوند؛ درس‌هایی که UID آن‌ها قبلاً وارد شده دوباره درج نمی‌شوند. برای به‌روزرسانی یک درس واردشده، UID جدید یا فرایند مهاجرت نسخه‌دار تعریف کنید؛ این واردکننده به‌صورت پیش‌فرض محتوای قبلی را overwrite نمی‌کند.

## عملکرد و پایداری\n\n- محتوای کامل در SQLite نگهداری می‌شود؛ برای سبک‌ماندن UI، فهرست درس‌ها باید فقط عنوان و UID را بخواند و متن کامل هنگام بازکردن درس واکشی شود.\n- بستهٔ JSON منبع محتوا باقی می‌ماند؛ فایل‌های ساخته‌شدهٔ Android فقط خروجی build هستند و نباید جای منبع اصلی را بگیرند.\n- اعتبارسنجی JSON و بررسی شمار درس‌ها/UIDها را قبل از انتشار اجرا کنید.
