# VALIDATION — دانشنامه دستورات فصل ۶۸

آخرین ممیزی مستند: ۲۰۲۶-۱۰-۱۷  
شاخه: `main`  
وضعیت کلی: `review_required` — انتشار نهایی تأیید نشده است.

## شمارهای اعلام‌شده در INDEX.json

- دستورات: ۳۷۵۰
- سؤال/پاسخ: ۱۲۷۰
- بسته‌های اصلی: MikroTik، Cisco IOS/IOS-XE، FortiGate/FortiOS، Linux، Windows mixed CMD/PowerShell، Windows Batch/CMD، Windows Server/AD و Docker
- بستهٔ فناوری‌های تکمیلی: ۱۵۰ رکورد در ۱۵ فناوری (میانگین ۱۰ رکورد برای هر فناوری)

> این اعداد از INDEX.json خوانده شده‌اند؛ تا زمان اجرای اعتبارسنج مستقل روی تمام فایل‌های واقعی، نباید آن‌ها را نتیجهٔ ممیزی نهایی تلقی کرد.

## وضعیت پوشش فناوری‌ها

- MikroTik / Cisco / FortiGate / Linux: هرکدام ۵۰۰ رکورد اعلام‌شده؛ نیازمند بازبینی syntax، نسخه، تکرار معنایی و سناریو.
- Windows Batch/CMD: ۵۰۰ رکورد اعلام‌شده؛ نیازمند اجرای نمونه‌ها و بررسی quoting و exit code.
- Windows mixed CMD/PowerShell: ۵۰۰ رکورد اعلام‌شده؛ نیازمند جداسازی معنایی و جلوگیری از هم‌پوشانی.
- Windows Server/AD و Docker: هرکدام ۳۰۰ رکورد اعلام‌شده؛ پایین‌تر از هدف ۵۰۰.
- فناوری‌های تکمیلی: SSH/OpenSSH، Telnet، FTP/FTPS/SFTP، VoIP/SIP/PBX، VMware ESXi، Zabbix، Wireshark/TShark، Juniper Junos، Aruba AOS-CX، Proxmox VE، Ansible، Terraform، Kubernetes، PowerShell و Hyper-V؛ هر فناوری فعلاً فقط سهم اولیه دارد، نه بستهٔ کامل.
- PowerShell مستقل هنوز نیازمند بستهٔ مستقل و تثبیت‌شده است؛ حضور آن در بستهٔ mixed ویندوز یا ۱۰ رکورد اولیه کافی نیست.

## کنترل‌هایی که پیش از تأیید نهایی باید اجرا و ثبت شوند

1. JSON parse و Schema validation برای تک‌تک فایل‌های بسته.
2. شمارش مستقل رکوردهای هر فایل و تطبیق آن با INDEX/manifest.
3. یکتایی UIDها در سطح هر فایل و کل فصل؛ تشخیص duplicate معنایی.
4. بررسی ارتباط سؤال و answer_key، نبود سؤال بدون پاسخ و پاسخ orphan.
5. کنترل فیلدهای ضروری، دستورهای خالی، مثال/خروجی، سطح دسترسی و یادداشت امنیتی.
6. اجرای `python scripts/assemble_chapter_packs.py --strict` در محیط مخزن.
7. اجرای تست جستجو و واردسازی در هر دو برنامهٔ Android و Windows.
8. ثبت لینک واقعی workflow و نتیجهٔ نهایی build/test؛ تا پیش از آن build را تأییدشده اعلام نکنید.

## معیار هدف

برای هر فناوری هدف‌گذاری‌شده: حداقل ۵۰۰ رکورد معنادار، حداقل ۱۰۰ مثال اجرایی و حداقل ۲۰ سناریوی انتها‌به‌انتها؛ آزمون‌ها با پاسخ‌نامهٔ جدا و UID پایدار. برای فناوری کوچک‌تر، هر استثنا باید مستند و مبتنی بر دامنهٔ واقعی باشد. رکوردهای تکراری یا نمونه‌های مصنوعی صرفاً برای افزایش شمارش قابل قبول نیستند.

## سیاست حفظ داده

تغییرات باید افزایشی باشند. محتوای قدیمی و UIDهای موجود حذف نشوند. هر فایل جدید باید با منبع canonical و فرایند build برنامه هماهنگ باشد.

**نتیجه:** فصل ۶۸ از نظر دسته‌بندی فناوری‌ها توسعه یافته، اما از نظر عمق محتوای هر فناوری و تأیید فنی هنوز کامل نیست. وضعیت `review_required` تا عبور تمام دروازه‌های بالا حفظ شود.
