NetworkAll · گالری اینفوگرافیک شبکه و فناوری

نمودارهای مرحله‌به‌مرحله برای فهم جریان واقعی داده، رفتار پروتکل‌ها و عیب‌یابی؛ از مدل ذهنی مبتدی تا نکته‌های عملیاتی پیشرفته.

روش مطالعه: ابتدا مسیر یا توالی را دنبال کنید؛ سپس توضیح زیر نمودار را بخوانید و در پایان آن را با خروجی ابزارهای واقعی مثل Wireshark، جدول MAC، جدول Route، لاگ DHCP/DNS یا تنظیمات VLAN تطبیق دهید.

این نمودارها مدل آموزشی‌اند؛ در شبکهٔ واقعی ممکن است مودم، ONT، روتر، سوئیچ و Access Point در یک دستگاه ادغام شده باشند. همیشه مسیر فیزیکی را از پیکربندی و شواهد همان شبکه تأیید کنید.

۱. مسیر یک Packet از کلاینت تا سرور

کلاینت مقصد IP را بررسی می‌کند. اگر مقصد خارج از subnet محلی باشد، بسته را به MAC آدرس Default Gateway می‌فرستد؛ برای یافتن MAC مقصد محلی/دروازه معمولاً ARP یا Neighbor Discovery به‌کار می‌رود.

  • Access Point: پل‌زدن ترافیک WLAN به LAN در حالت رایج.
  • Switch: ارسال فریم بر پایهٔ MAC و VLAN.
  • Router/Firewall: بررسی جدول Route، اعمال سیاست، کم‌کردن TTL/Hop Limit و ساخت سربرگ لایهٔ پیوندِ خروجی جدید.
  • ONT/Modem: تبدیل/انتقال رسانهٔ دسترسی؛ در دستگاه‌های یکپارچه ممکن است نقش روتر هم داشته باشد.

NAT فقط در صورت پیکربندی و نیاز مسیر رخ می‌دهد. مسیر برگشت معمولاً برعکس است، اما الزاماً همان مسیر فیزیکی را طی نمی‌کند.

۲. تفاوت Switch و Router

  • سوئیچ از Source MAC ورودی جدول MAC/CAM را یاد می‌گیرد و با Destination MAC در VLAN مربوطه تصمیم می‌گیرد.
  • اگر مقصد MAC ناشناخته باشد، فریم در همان VLAN روی پورت‌های مناسب flood می‌شود؛ broadcast هم در دامنهٔ VLAN محدود است.
  • روتر با آدرس مقصد IP، longest-prefix match و next hop/interface را انتخاب می‌کند؛ هر اینترفیس لایهٔ ۳ یک مرز مسیریابی است.
  • VLANها را با trunk/access و تنظیمات gateway به هم متصل کنید؛ صرف ساختن VLANها ارتباط بین آن‌ها ایجاد نمی‌کند.

آزمایش: جدول MAC، VLAN membership، جدول Route، ARP/neighbor و شمارنده‌های interface را با هم مقایسه کنید.

۳. Encapsulation از داده تا بیت

  • Application: دادهٔ برنامه مثل درخواست HTTP.
  • Transport: پورت‌های TCP/UDP؛ TCP علاوه بر پورت‌ها شمارهٔ توالی، ACK و کنترل جریان/ازدحام دارد.
  • Network: آدرس IP مبدأ/مقصد و TTL یا Hop Limit.
  • Link: آدرس MAC محلی، EtherType و FCS برای تشخیص خطای فریم در Ethernet.
  • Physical: نمایش بیت‌ها روی رسانهٔ فیزیکی یا امواج رادیویی.

در هر hop، روتر معمولاً فریم جدیدی می‌سازد؛ IP مبدأ/مقصد غالباً باقی می‌ماند مگر NAT، تونل، پراکسی یا سازوکار دیگری آن را تغییر دهد.

۴. دریافت IP با DHCP (DORA)

  • Discover: کلاینتی که هنوز IP ندارد، برای یافتن DHCP Server پیام می‌فرستد.
  • Offer: سرور یک lease پیشنهادی با IP و optionها اعلام می‌کند.
  • Request: کلاینت پیشنهاد موردنظرش را درخواست می‌کند.
  • ACK: سرور lease را تأیید می‌کند؛ کلاینت باید تنظیمات و مسیر را اعتبارسنجی کند.

علاوه بر IP، subnet mask/prefix، default gateway، DNS و lease time اهمیت دارند. در شبکهٔ دارای VLAN، DHCP relay/IP helper می‌تواند درخواست broadcast را به سرور دیگر برساند.

۵. DNS؛ از نام تا آدرس

  • برنامه معمولاً از stub resolver سیستم‌عامل درخواست می‌کند؛ cache محلی/سازمانی ممکن است پاسخ دهد.
  • Resolver بازگشتی در صورت cache miss زنجیرهٔ delegation را دنبال می‌کند: Root، TLD و authoritative.
  • TTL مدت مجاز cache را مشخص می‌کند. A برای IPv4 و AAAA برای IPv6 است؛ CNAME نام مستعار تعریف می‌کند.
  • اختلال DNS را از مشکل اتصال IP جدا کنید: بررسی resolver، پاسخ، TTL، split DNS، پورت ۵۳/DoT/DoH و suffix جست‌وجو.

آزمایش: خروجی `nslookup` یا `dig +trace` را با cache، رکورد authoritative و مسیر شبکه مقایسه کنید.

۶. اتصال Wi‑Fi سازمانی و عبور ترافیک

  • کلاینت اسکن، Authentication/Association و در شبکه‌های امن سازوکار امنیتی/کلید را طی می‌کند.
  • AP ترافیک را به VLAN/SSID درست نگاشت می‌کند؛ uplink ممکن است access یا trunk باشد.
  • DHCP، DNS، default gateway، ACL/firewall و مسیر WAN مراحل مجزایی‌اند؛ هرکدام باید جدا بررسی شوند.
  • در roaming، کلاینت بین APها جابه‌جا می‌شود؛ کیفیت RF، کانال، توان، تداخل، پوشش و احراز هویت مهم‌اند.

عیب‌یابی را از لایهٔ رادیویی به بالا انجام دهید: Association → VLAN → DHCP → DNS → Gateway → Route/NAT → مقصد.

۷. بوت Windows از UEFI تا Sign-in

زنجیرهٔ کلی شامل UEFI/POST، Windows Boot Manager، خواندن BCD، اجرای winload، راه‌اندازی kernel و سپس سرویس‌های user mode است. Secure Boot طبق policy firmware زنجیرهٔ بوت را اعتبارسنجی می‌کند.

برای عیب‌یابی، نقطهٔ شکست و کد خطا را ثبت کنید. تغییر BCD یا پارتیشن EFI فقط با شناخت سیستم، backup و رسانهٔ بازیابی انجام شود.

۸. بوت Linux، initramfs و systemd

Firmware، bootloader، kernel/initramfs، mount شدن root filesystem و PID 1 مراحل اصلی مدل رایج‌اند. سیستم‌هایی که systemd ندارند یا معماری embedded خاص دارند، ممکن است مسیر متفاوتی داشته باشند.

برای شروع، خروجی journalctl -b -1، systemctl --failed و findmnt / را جمع کنید؛ پیش از بازسازی initramfs، نسخهٔ kernel و شناسهٔ root را تأیید کنید.

۹. چرخهٔ Git؛ از تغییر تا Remote

Working tree تغییرات فایل‌ها، index فهرست تغییراتی که قرار است commit شوند و commit یک snapshot قابل‌ارجاع است. Remote و pull request لایه‌های همکاری‌اند که پس از push قابل بازبینی می‌شوند.

برای عملیات خطرناک، git status و git diff را قبل و بعد ببینید؛ برای خنثی‌کردن commit مشترک غالباً git revert از بازنویسی تاریخچه امن‌تر است.

۱۰. PowerShell Pipeline و Objectها

Pipeline اجازه می‌دهد objectها فیلتر، مرتب، انتخاب و ذخیره شوند؛ این روش از parse کردن متن خروجی فرمان‌ها پایدارتر است. در automation، خطا، نوع داده، ورودی نامعتبر و نتیجهٔ قابل‌راستی‌آزمایی را جدا مدیریت کنید.

برای خروجی machine-readable از Export-Csv یا JSON متناسب با مصرف‌کننده استفاده کنید؛ Format-Table داده را برای نمایش قالب‌بندی می‌کند و نباید پیش از export قرار گیرد.

۱۱. Backup، Restore و معیار بازیابی

RPO میزان از دست‌رفتن دادهٔ قابل‌قبول و RTO زمان هدف برای برگشت سرویس است. نسخهٔ آفلاین یا immutable باید از اعتبارنامهٔ معمول و دامنهٔ خرابی/نفوذ جدا محافظت شود.

Restore را در محیط ایزوله انجام دهید و صحت داده، وابستگی‌ها و کارکرد برنامه را بسنجید. زمان بازیابی واقعی و خطاهای آزمون را ثبت کنید و runbook را به‌روز نگه دارید.

۱۲. ARP در IPv4 و Neighbor Discovery در IPv6

ARP آدرس IPv4 را به آدرس لایهٔ پیوند در همان شبکه نگاشت می‌کند. IPv6 از Neighbor Discovery روی ICMPv6 استفاده می‌کند و علاوه بر نگاشت همسایه، قابلیت‌هایی مانند Router Discovery و Duplicate Address Detection دارد.

  • Windows: arp -a و Get-NetNeighbor
  • Linux: ip neigh show
  • در رخداد مشکل، VLAN، IP تکراری، cache کهنه و drop شدن ARP/ICMPv6 را بررسی کنید.

۱۳. TCP سه‌مرحله‌ای و پایان اتصال

در handshake، طرفین شماره‌های توالی را هماهنگ می‌کنند. پس از برقراری اتصال، ACK، window و retransmission در رفتار واقعی مهم‌اند. پایان graceful معمولاً FIN/ACKهای دوطرفه دارد، درحالی‌که RST اتصال را به‌صورت ناگهانی خاتمه می‌دهد.

  • اگر SYN خارج می‌شود ولی SYN-ACK نمی‌آید، مسیر برگشت، ACL/firewall، listener و مقصد را بررسی کنید.
  • اگر TCP برقرار است اما وب کار نمی‌کند، TLS certificate/time، HTTP status و لاگ برنامه را جدا بررسی کنید.

۱۴. VLAN، Access و Trunk

Access port یک VLAN را به پورت کلاینت نسبت می‌دهد؛ فریم سمت میزبان در سناریوی متداول بی‌تگ است. Trunk با 802.1Q شناسهٔ VLAN را برای VLANهای مجاز حمل می‌کند. Native VLAN و allowed VLAN list باید با طراحی هر دو سمت سازگار باشند.

آزمایش: پیکربندی دو سمت trunk، MAC table/VLAN membership و gateway را بررسی کنید؛ سپس ارتباط درون VLAN و بین VLANها را جداگانه تأیید کنید.

۱۵. NAT و PAT؛ ترجمهٔ آدرس و پورت

PAT جریان‌ها را با آدرس/پورت مبدأ ترجمه‌شده و state اتصال از هم تفکیک می‌کند. پاسخ باید با state و مسیر برگشت سازگار باشد. Double NAT یا CGNAT می‌تواند انتشار سرویس و inbound connectivity را پیچیده کند.

برای عیب‌یابی، جدول translation/conntrack، WAN IP، default route، policy firewall و مسیر برگشت را بررسی کنید؛ قبل از تغییر Port Forwarding وضعیت مالکیت public IP را تأیید کنید.

۱۶. Stateful Firewall؛ چرا پاسخ یک اتصال با اتصال جدید فرق دارد؟

Firewall ممکن است zone/interface، tuple اتصال، state پروتکل، ترتیب rule، NAT و سیاست را با هم ارزیابی کند. ترافیک برگشتی یک جریان مجاز گاهی به دلیل state پذیرفته می‌شود؛ این موضوع مجوز عمومی برای اتصال جدید نیست.

در lab ایزوله، یک قانون را تغییر دهید، counters/log/conntrack را قبل و بعد مقایسه کنید و rollback را آماده نگه دارید. NAT و firewall را به‌عنوان دو نقش مرتبط اما متفاوت بررسی کنید.

۱۷. همگرایی OSPF؛ از Hello تا FIB

Hello همسایه را شناسایی می‌کند؛ adjacency و تبادل/flood اطلاعات لینک‌استیت پایگاه LSDB را همگرا می‌کنند. سپس الگوریتم SPF مسیرها را محاسبه می‌کند و نتیجه پس از قواعد انتخاب route در RIB و صفحهٔ forwarding نصب می‌شود.

عیب‌یابی را مرحله‌ای انجام دهید: neighbor state، area/timers/authentication، LSDB، SPF/RIB، next-hop resolution، FIB و شمارنده‌های interface. جزئیات وابسته به area، network type و پیاده‌سازی است.

۱۸. محل درست Packet Capture در مسیر

ثبت packet از یک نقطه فقط همان دید محلی را نشان می‌دهد. اگر بسته در کلاینت دیده شود ولی در mirror port نباشد، لایهٔ دسترسی، VLAN، پورت mirror و dropهای محلی را بررسی کنید؛ اگر از WAN خارج شود اما پاسخی نرسد، upstream و مسیر برگشت را دنبال کنید.

زمان، interface، فیلتر، نرخ packet loss، offload و محدودیت‌های مشاهدهٔ TLS را در گزارش ثبت کنید؛ capture را بدون مجوز یا ضرورت از محتوای حساس تهیه نکنید.

۱۹. درخت تصمیم عیب‌یابی شبکه

رویهٔ قابل تکرار: symptom → evidence → hypothesis → discriminating test → root cause → low-risk remediation → independent verification. ابتدا شواهد و baseline را ثبت کنید؛ هم‌زمان چند متغیر را تغییر ندهید.

ابزار مناسب به پلتفرم بستگی دارد: Test-NetConnection، ipconfig /all، ip route، resolvectl، جدول MAC/Route و packet capture. خروجی هر فرمان باید تفسیر شود، نه فقط اجرا.

۲۰. مودم، ONT و حالت Bridge در برابر Router

در Bridge mode، تجهیزات کاربر معمولاً اتصال WAN مثل PPPoE، route و NAT را انجام می‌دهند. در Router mode، CPE می‌تواند DHCP، NAT، firewall و Wi-Fi را خودش مدیریت کند. قرار گرفتن یک روتر پشت روتر دیگر ممکن است Double NAT بسازد.

برای تشخیص، WAN IP، default route، DHCP server، bridge/VLAN، PPPoE و conntrack را بررسی کنید. تغییر حالت دستگاه ممکن است دسترسی مدیریت و سرویس را قطع کند؛ تنظیم فعلی و روش بازگشت را قبل از تغییر ثبت کنید.

۲۱. EVPN/VXLAN؛ Underlay در برابر Overlay

Underlay مسیر IP بین VTEPها را فراهم می‌کند؛ VXLAN فریم tenant را encapsulate می‌کند و EVPN reachability را در control plane منتشر می‌کند. VNI و VLAN ID برابرِ معنایی ندارند و به mapping وابسته‌اند.

در رخداد، underlay RIB/FIB، EVPN RIB/route type، RT/VNI mapping، remote MAC/IP state، MTU و packet capture بیرونی/داخلی را جدا بررسی کنید.

۲۲. SD-WAN + SASE؛ Path Selection تا Security Policy

SD-WAN می‌تواند مسیر را براساس SLA و نوع برنامه انتخاب کند. SASE ممکن است هویت/وضعیت دستگاه و سیاست‌های ZTNA، SWG یا FWaaS را در مسیر بررسی کند. سلامت لینک یا ورود موفق به‌تنهایی دسترسی مجاز به application را ثابت نمی‌کند.

برای پذیرش، application transaction، p95/p99 latency، loss/jitter، policy decision logs، failover و rollback را اندازه‌گیری کنید.

۲۱. RouterOS — مسیر Packet و Firewall Chains

Input برای ترافیک مقصد خود روتر، forward برای ترافیک عبوری و output برای ترافیک تولیدی خود روتر است. NAT ترجمه انجام می‌دهد اما جایگزین Firewall policy نیست. برای RCA، route table، conntrack/NAT state، rule counters و capture را به یک flow مشخص مرتبط کن.

این نمودار مفهومی است؛ packet-flow رسمی و رفتارهای IPv4/IPv6 را در release هدف بررسی کن.

۲۲. QoS — Queue، PCQ و نقطهٔ ازدحام

Simple Queue، Queue Tree و PCQ سیاست‌های متفاوتی برای rate، priority و تقسیم منابع دارند. قبل و بعد از تنظیم، throughput، p95 latency، jitter، loss و queue drops را با چند client و mixed traffic اندازه‌گیری کن. FastTrack ممکن است در برخی نسخه‌ها و queue typeها مسیر عادی queue/mangle را دور بزند.

۲۳. VPN و VRRP — تونل و دسترس‌پذیری

VRRP مالکیت virtual gateway را تغییر می‌دهد؛ NAT/conntrack و VPN sessionها لزوماً sync نمی‌شوند. در تست failover، existing و new flows، زمان بازیابی، packet loss، tunnel state و application probe را جدا ثبت کن. سناریوهای قطع روتر و قطع upstream را جداگانه بررسی کن.
