# استاندارد کیفیت، ساختار و نگه‌داری محتوای NetworkEncyclopedia

## اصل راهبردی

مخزن محتوای آموزشی است، نه مجموعه‌ای از خلاصه‌های کوتاه. مسیر آموزش باید از L0 (بدون پیش‌نیاز) تا L4 (طراحی، عیب‌یابی پیچیده و تصمیم‌گیری معماری) پیوسته باشد. **کم‌عمق بودن یک فصل دلیل حذف آن نیست**: ممیزی ابتدا شکاف را ثبت می‌کند؛ سپس همان UID یا نسخهٔ جایگزین با محتوای بهتر تکمیل می‌شود. حذف فقط برای رکورد تکراریِ دقیق یا محتوای دارای جایگزین تأییدشده مجاز است.

## ساختار منبع محتوا

- فایل‌های JSON نهایی فقط زیر tools/packs/<domain>/ نگه‌داری می‌شوند.
- tools/packs/pack_catalog.json فهرست مسیرهای رسمی، دامنه، فصل هدف و وضعیت ممیزی است.
- tools/engineer_jokar_* ابزار تولید، اعتبارسنجی و مستندات موضوعی هستند؛ محل آرشیو JSON نهایی نیستند.
- tools/chapter_prompts و پوشه‌های prompts فقط متن پرامپت دارند.
- server/core/full_curriculum.py ساختار پایهٔ درخت را تعریف می‌کند.
- scripts/export_android_index.py و scripts/merge_content_packs_into_android.py خروجی آفلاین اندروید را می‌سازند.
- پایگاه داده، کلید رمزها، بکاپ‌های کاربر و فایل‌های APK جزو محتوای Git نیستند.

## حداقل قرارداد هر درس

هر درس کاربردی باید این اجزا را داشته باشد. تنها وجود عنوان بخش کافی نیست؛ متن آن باید با موضوع درس مرتبط و قابل اجرا باشد.

1. هدف و نتیجهٔ قابل سنجش
2. پیش‌نیازها، واژه‌های پایه و محیط اجرا/نسخه
3. توضیح مفهومی از «چرا» و مدل ذهنی
4. سازوکار داخلی، جریان داده/کنترل و ارتباط با اجزای دیگر
5. Syntax، پارامترها، خروجی و مثال توضیح‌دار
6. مثال حل‌شده از ابتدا تا راستی‌آزمایی
7. لابراتوار ایزوله با توپولوژی، آدرس‌دهی، مراحل، خروجی مورد انتظار و cleanup
8. سناریوی واقعی همراه قیود و معیار موفقیت
9. عیب‌یابی از نشانه تا علت ریشه‌ای و روش تأیید علت
10. امنیت، ریسک تغییر، rollback و خطاهای رایج
11. پرسش‌ها در یک ساختار مستقل و پاسخ‌نامهٔ جدا با توضیح
12. منابع سازنده/استاندارد، تاریخ بازبینی و نسخهٔ فناوری
13. جمع‌بندی، واژه‌نامه و مسیر بعدی یادگیری

### معیار عمق پیشنهادی

- L0: تعریف ساده، تشبیه درست، پیش‌نیاز صفر و مثال کوچک.
- L1: مراحل پایه، فرمان‌های اصلی و یک آزمایش قابل تکرار.
- L2: چند حالت کاربرد، خروجی نمونه، خطاهای متداول و سناریوی عملی.
- L3: تعامل فناوری‌ها، طراحی، عیب‌یابی چندمرحله‌ای، امنیت و trade-off.
- L4: معماری، ظرفیت/مقیاس، failure mode، migration/rollback، سناریوی چندبخشی و دفاع از تصمیم فنی.

طول متن شاخص کمکی است: کمتر از ۸۰۰ نویسهٔ توضیحی معمولاً نیازمند بازبینی، ۸۰۰ تا ۱۹۹۹ متوسط، و ۲۰۰۰ نویسه یا بیشتر نامزد محتوای عمیق است. **عبور از آستانهٔ طول، تأیید علمی یا عملی نیست.**

## آزمون محتوایی و یکپارچگی

- JSON باید معتبر باشد؛ UID و موقعیت ساختاری نباید تکراری شوند.
- هر سؤال باید ID داشته باشد و برای آن پاسخ مستقل هم‌ID با دلیل درج شود.
- پاسخ درست نباید به متن سؤال یا گزینه‌ها نشت کند.
- مثال‌های CLI باید پیش‌نیاز، حالت privilege/config، نسخه یا خانوادهٔ تجهیزات و خروجی مورد انتظار را مشخص کنند.
- مثال‌های مخرب یا پرخطر باید محیط ایزوله، backup، rollback و محدودهٔ مجاز داشته باشند.
- audit_content.py گزارش سطح عمق، markerهای لابراتوار/مثال/امنیت/راستی‌آزمایی، آزمون‌ها، duplicateها و ضعیف‌ترین رکوردها را می‌سازد.
- گزارش ممیزی نباید به‌تنهایی باعث پاک‌شدن فایل یا درس شود. تغییرات محتوا پس از بررسی فنی و مقایسهٔ گزارش‌ها وارد شاخه می‌شوند.

## راهبرد فایل‌های بزرگ و سرعت اجرا

- حجم JSON مشکلی نیست؛ parse کامل بانک در هر درخواست وب مشکل است.
- جست‌وجو باید SQLite FTS/index یا query محدود داشته باشد؛ درخواست نتیجهٔ محدود و صفحه‌بندی‌شده بگیرد.
- فهرست درختی با lazy loading بارگذاری شود و متن کامل درس فقط هنگام بازشدن آن fetch شود.
- اندروید از asset فشردهٔ curriculum و Room محلی استفاده می‌کند؛ از نگهداری دو نسخهٔ کامل و نامنسجم از محتوای یکسان در چند مسیر خودداری کنید.
- عملیات seed/repair نباید دیتابیس غیرخالی یا پیشرفت کاربر را خودکار حذف کند. هر import بزرگ باید dry-run، backup، تراکنش و گزارش رکوردهای تغییرکرده داشته باشد.

## قابلیت‌های شخصی و داده‌ها

این برنامه برای استفادهٔ شخصی محلی طراحی شده است. در حالت پیش‌فرض Flask فقط روی 127.0.0.1 گوش می‌دهد. برای Sync گوشی، کاربر باید آگاهانه LAN را فعال کند، token قوی تعیین کند و Firewall را به شبکهٔ Private محدود کند. هرگز port forwarding روتر یا دسترسی اینترنت عمومی برای این برنامه ایجاد نکنید.

تقویم/وظایف شمسی روی هر دو سکو محلی است. یادآوری ویندوز در زمان اجرای سرور کار می‌کند؛ یادآوری اندروید با WorkManager زمان‌بندی می‌شود و به اجازهٔ اعلان سیستم‌عامل نیاز دارد. برای حفاظت از secrets، کلید/DB را در Git قرار ندهید و دادهٔ رمز را در صورت شکست رمزنگاری هرگز به متن ساده ذخیره نکنید.


## منابع فعال، منبع قرنطینه و واردسازی Git

- `tools/packs/pack_catalog.json` مرجع وضعیت و مسیر بسته‌هاست؛ `tools/packs/` مسیر canonical محتوای فعال است.
- کتاب Git فصل ۶۴ در `tools/packs/git_chapter64/Git_Chapter_64_Full.md` نگهداری می‌شود. واردکننده آن را بر اساس عنوان‌های سطح‌دار به درس تبدیل می‌کند و پیش از افزودن، عنوان موجود را تطبیق می‌دهد تا یک درس دوبار نمایش داده نشود.
- بسته‌های OSPF/BGP و VPN در مسیرهای canonical خودشان نگهداری می‌شوند؛ فایل‌های سخت‌افزاری قدیمی که نام OSPF/VPN داشتند از شاخهٔ کاری حذف شده‌اند و دیگر منبع محتوای این فصل‌ها نیستند.
- بستهٔ امنیت اخلاقیِ قالب‌محور با حفظ فایل اصلی از ادغام فعال خارج شده است. تا زمان بازنویسی اختصاصی هر موضوع، نباید به‌عنوان کتاب نهایی نمایش داده شود. گزارش ممیزی همچنان آن را بررسی می‌کند تا پس از اصلاح دوباره وارد چرخه شود.
- در ادغام فرمان‌ها، UID باید هم منبع و هم رکورد را از هم متمایز کند. شناسه‌های قدیمیِ مبتنی بر شمارهٔ ردیف پیش از ساخت دوباره حذف می‌شوند؛ اگر دو بسته UID یکسان اما عنوان متفاوت داشته باشند، درس دوم با UID پایدار جایگزین حفظ می‌شود.
- ادغام نباید فصل موجود را با یک آرایهٔ جدید جایگزین کند. ابتدا تطبیق عنوان، سپس افزودن فقط درس‌های واقعاً جدید انجام می‌شود؛ درس تکراری بر اساس عنوان دوباره افزوده نمی‌شود.
